# Affiliate Website Project Rules

## Project Purpose
This project is an affiliate website project intended to support multiple products and, eventually, multiple independently deployable affiliate websites.

## Current Project
The current website is "01-Product Guide" and is an existing Yu Sleep affiliate website.

## Safety Rules
- Do not delete files unless explicitly instructed.
- Do not rename files unless explicitly instructed.
- Do not change affiliate URLs unless explicitly instructed.
- Do not replace product claims, pricing, guarantees, or ingredient information with invented information.
- Do not invent product facts.
- Do not modify legal pages without explicit instruction.
- Before making large changes, inspect the relevant files first.
- Prefer small, reviewable changes over large uncontrolled rewrites.

## HTML Rules
- Use semantic HTML.
- Maintain one clear H1 per primary page unless there is a specific reason not to.
- Preserve meaningful heading hierarchy.
- Keep navigation and internal links functional.
- Keep accessibility in mind.

## CSS Rules
- Preserve responsive behavior.
- Prefer reusable classes and existing design tokens.
- Avoid unnecessary inline styles.
- Do not introduce a CSS framework unless explicitly instructed.
- Check desktop, tablet, and mobile behavior after significant CSS changes.

## SEO Rules
- Preserve and improve title tags and meta descriptions.
- Use appropriate canonical URLs.
- Keep robots.txt and sitemap.xml consistent with the live domain.
- Use descriptive image alt text.
- Do not create misleading SEO content.
- Do not use keyword stuffing.
- Preserve crawlable internal navigation.

## Affiliate Rules
- Affiliate destinations must be explicitly configured.
- Do not invent affiliate URLs.
- CTA links should be consistent and easy to update.
- Keep affiliate disclosure information visible and accurate.

## Product Content Rules
- Product names, ingredients, prices, guarantees, bonuses, and claims are product-specific.
- Never copy product-specific factual claims to another product without verification.
- Product images and brand assets must remain product-specific.

## Multi-Website Architecture
- Reusable layout, styling, and components may be shared.
- Product content, product images, affiliate URLs, domains, SEO metadata, and brand identity must remain site-specific.
- Each final website should remain independently deployable.
- Avoid tightly coupling one site's product content to another site's website.

## Git Rules
- Work on the appropriate development branch when making changes.
- Do not rewrite Git history unless explicitly instructed.
- Before major changes, inspect git status.
- Keep changes focused and reviewable.

## Review Rules
- After making changes, summarize exactly what was changed.
- Report any files modified, created, or deleted.
- Identify any unresolved issues or assumptions.
- Do not claim that something was tested if it was not actually tested.
